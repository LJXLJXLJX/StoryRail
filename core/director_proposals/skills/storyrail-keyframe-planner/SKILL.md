# Segment 关键帧规划

关键帧不是剧情插图，也不是“电影感”修饰词的集合，而是某一精确时间点的、可直接进入生产的摄影画面。
本 Skill 负责把已经批准的镜头设计落实为空间明确、叙事重点清楚的静态边界。它不能暗中改写
Scene、Shot、Segment、对白、旁白、动作结果或时长；若上游镜头设计不足，只能在既定意图内具体化。

结构化导演脚本已经是镜头功能、第一视觉重心、人物调度、连续性锚点、揭示路径和起止状态的上游权威。
本 Skill 不得重新选择景别、机位、角色关系或剧情揭示；若这些信息缺失或互相冲突，应报告脚本需要回改，
而不是用关键帧正文悄悄补写导演决定。

复杂调度、跨镜连续、揭示信息或 `9:16` / `2:1` 构图时，必须阅读
[`references/cinematic-keyframe-design.md`](references/cinematic-keyframe-design.md)；
撰写每张帧的画面正文前，必须阅读
[`references/cinematic-frame-prompting.md`](references/cinematic-frame-prompting.md)。
必须遵守全局 `storyrail-image-prompt-writing`（契约 `global/` 资源或工作集 `image_prompt.global_skills`）：
有输入图时把“逐图标签与用途 + 正文显式引用”完整写进提示词，不写文件名；没有输入图时只写画面正文。
工作集 `image_prompt` 给出当前生图/改图插件的输入图指代约定；其 `plugin_skills` 目录非空时，正文写法还必须遵守
随插件发布的专业 Skill（例如 `qwen-image-prompt-writing`，全文在本契约的 `plugin/` 资源中），它只改变正文的组织方式，不改变本 Skill 的画面决定。

## 静默设计顺序

先读完整 Scene 作为上下文，按以下顺序判断，最后只输出 schema。读取完整 Scene 不扩大本轮允许修改的 Segment 范围；
`planning_enabled=false` / `context_segment_ids` 只供阅读，输出的 `segments` 必须严格按 `writable_segment_ids`
顺序且只包含这些授权 Segment。需要新建、解除或改写与上下文 Segment 的共享边界时，应报告必须扩大的最小相邻 Segment，不能替上下文 Segment 编造提案。
`saved_keyframe_plan` 是当前 scope 内已经持久化的计划事实：共享 Keyframe 按 ID 去重，`bindings`
列出它在多个 Segment 的实际首尾用途，不能把 `owner_segment_id` 误解为唯一使用者。它不依赖图片生成就绪；
实际可提交 Provider 的图片映射仍以单独的可执行输入为准，不能把保存的正文或 selected_asset_id 为 null 的槽位称为可生成输入。

1. **连续关系**：先区分切镜与真正一镜到底，将相邻 Segment（无论是否共享边界 Shot）作为一个完整摄影过程理解，确定每个分段的交接时刻。不能先独立设计各 Segment 的代表构图，再拼接不相容的首尾帧。一个 Segment 覆盖多个 Shot 时，段内切镜是软约束，只有首/尾时刻需要静态帧。
2. **整段变化**：沿已批准的动作与摄影机运动，梳理起点、经过和终点；检查哪些人物、环境、道具或身份特征会被新揭示。运动用于内部推演，不写进静态画面正文。
3. **实际输入**：先读 `video_inputs`：当前 recipe、合法 `frame_strategies`、槽位声明、已绑定的 `reference_inputs` 与已有 `reference_image_plans`。视频只看到显式绑定的素材；角色卡、地点资料和生图辅助图不会自动进入视频。把身份、空间和道具参考与精确起止画面的时间约束分别判断。
4. **边界状态**：把连续过程落实为具体首尾时刻；共享交接只能设计一次。若脚本要求交接瞬间跳到不同机位，又要求一镜到底，不能暗改动作或假装共享解决了冲突，应交由 Director 澄清或显式回改脚本。
5. **帧数选择**：分别判断是否需要精确起点、精确终点以及连续交接。通常从单首帧评估；没有独立结束构图或必须交接的尾帧，就不启用尾帧。支持独立参考的 recipe 可用无时间位置图片承载身份与空间信息，允许首尾均不启用；不把普通动作结果、表情变化或人物进出自动当作双帧理由。

随后对每张必要的静态边界细化：

1. **叙事功能**：观众此刻必须先看见什么、理解什么或期待什么。
2. **视觉命题**：确定唯一第一视觉重心，以及必要的第二层信息；不要让所有元素同等重要。
3. **人物调度**：先确定人物与物体在空间中的站位、朝向、视线、重心和遮挡，再描述摄影机。
4. **摄影机立场**：忠实落实既有景别、角度和运动意图，用可见空间关系表达，不擅自换镜头。
5. **剪辑关系**：检查动作方向、视线、轴线、道具状态、光线以及前后景别变化。
6. **生成可行性**：选择姿态稳定、轮廓清楚、手部和遮挡可控的静止瞬间，不冻结在模糊动作中途。

## 画面描述必须具体

每个首帧和尾帧应按画面需要写清：

- 权威画幅、景别与摄影机观察位置；
- 左、中、右及前景、中景、背景的空间分配；
- 每个可见角色的位置、朝向、视线、身体重心、手部或接触关系；
- 关键道具的位置、状态与归属；
- 环境中需要变化或新出现的部分；结合 Scene setting、地点语义、状态和地点图片说明自行建立完整空间，不假设任何地点图片会自动作为生图输入；
- 光源方向、明暗关系，以及观众首先应注意的对象；
- 若是首帧，给后续动作留下可读的空间和动势；若是尾帧，明确动作结果和下一剪辑点。

禁止用“电影感、高质量、氛围感、构图优美、史诗感”等抽象词代替这些可见事实。不得写动作过程、
镜头运动过程、视频提示词、帧率、模型名或 Provider 参数。

## 画幅不是裁切参数

- `16:9` 可以利用横向关系、多人横向调度和环境宽度。
- `9:16` 必须原生设计纵深与上下层次，主体和关键动作放在安全中心区域；不要先按横屏构图再裁两边。
- `2:1` 是更宽更扁的宽银幕，用横向留白、左右分区和前景遮挡组织画面；头顶与脚下空间更少，
  不要先按 16:9 构图再裁上下。
- 无论画幅如何，必须保持清晰轮廓、可读视线和足够的动作空间。
- `start_prompt_text` 和 `end_prompt_text` 保存全局 Skill 要求的完整提示词，有输入图时包含逐图用途与正文；不写 `9:16`、`16:9`、`2:1`、竖幅、横幅或宽银幕标签；
  画幅由 Core 在实际提交时固定编译，不能形成两个来源。

## 首尾槽位与最少约束

- Core 为每个 Segment 保留首尾两个时间语义槽位，但不要求两张都生成。
- `start`：只锁定起点。固定机位、小动作、表情变化、推近已知主体通常先考虑单首帧；动作过程交给视频模型。
- `end`：只需要确定终点构图或与下一段交接，起点可由视频生成时使用。
- `both`：起点、终点各有独立且必要的时间约束，或连续组必须承接两个共享边界时使用。逐端指出新增约束，不能用“更稳妥”“保证一致”代替判断。
- `none`：当前 `video_inputs[].frame_strategies` 允许时，可只用显式独立图片、音频或视频参考，不锁定首尾时刻。缺少必要参考时说明需要规划/添加的素材，不能声称已经提交；Core 会在视频生成前校验媒体输入。
- 局部拉远揭示人物、房间或道具时，先判断独立参考是否已交代这些信息；只有确实需要锁定局部起点和揭示后的结束画面才使用双帧。首尾图必须对应真实起止时刻。
- 每个 Segment 输出 `frame_strategy=none|start|end|both`；只给启用且不继承的端点填写正文和角色，未启用端点可用空字符串与空数组，不需要为了通过 schema 编造另一张画面。Core 保留未启用端点已有计划。
- 首帧对应第一个覆盖 Shot 的开头，尾帧对应最后一个覆盖 Shot 的结尾。段内切镜主要由视频提示词表达，不为所有 Shot 强制画边界帧。
- `continues_from_previous=true` 表示显式共用同一交接图，首帧字段为空；真正共享边界仍要求前段尾帧、后段首帧启用。不要为了减少图片破坏已经明确的共享交接。
- `reference_images` 是可选增补数组，最多 4 项：`slot_index`（0–3）、`prompt_text`、`description`、`visible_character_ids`、`character_references`、`reference_asset_ids`。只规划当前 recipe 支持的其他图片槽位，沿用已有槽位，不重复规划已选图片或已有成功候选；未列出的规划保留。
- 其他图片没有视频时间位置，可以是任意画面内容，包括人物、空间、物件、图案、风格示意或用户指定的其他图片；不要求来自关键帧、角色卡或地点库。按缺失信息选择最少必要图片，不能因为有四张卡片就填满四张。`description` 说明预期参考用途，生成后人类按真实画面确认；规划不生成、不选择、不改已有视频输入绑定。
- 首帧应是“动作即将发生”的稳定时刻：意图可读、动势未耗尽、运动空间明确。
- 尾帧应是“动作已经成立”的稳定时刻：结果清楚，可作为停顿或剪辑点。

## 相邻 Segment 的连续边界

`continues_from_previous=true` 表示两边复用**同一张像素级关键帧**，不仅是剧情连续。只有摄影机位置、
景别、构图、人物姿态、道具和光线状态在交接的同一时刻完全相同时才能设置。相邻 Segment 共享边界 Shot
时通常应延续；普通正反打、切镜或明确换机位使用 `false`。一镜到底中的推近、绕行、拉远或景别变化发生在
Segment 内，不是切镜理由：必须先设计交接时刻，再从该时刻继续运动，不能比较两个 Segment 的代表构图后拒绝共享。
Director 本轮采用的连续长镜头方案即使记录在 `director_hypotheses`，也应落实为真实共享边界；
`required_shared_boundaries` 是最低强制集合，空数组不表示禁止或不需要共享。

设置为 `true` 时，当前 Segment 的 `start_*` 字段必须为空：`start_prompt_text=""`、
`start_visible_character_ids=[]`、`start_character_references=[]`；Core 沿用上一 Segment 的 `end_*`。
每个 Scene 的第一个 Segment 必须为 `false`。

相邻 Segment 不共享边界 Shot（明确切镜）时，`continues_from_previous=false`，两个边界默认是独立 Keyframe：
后段必须给出自己的 `start_*` 描述。也可显式共享为同一个 Keyframe，但像素级连续性要求不变。

当 Core 提供 `required_shared_boundaries` 时，表示 Director 已把本轮采用的连续镜头方案解析成必须共用的
时间边界，列出的是相邻 Segment 对。对应后一 Segment 必须设置 `continues_from_previous=true`；即使它随后
改变机位或景别，变化也只能发生在这个共用首帧之后。不得把该硬约束降级为仅保持人物、道具、光线或轴线状态相似。

共享同一图片只约束交接画面，不保证运动自动无缝；还要沿原脚本核对动作阶段、运动方向和摄影机运动的衔接。

## 实际视频输入边界

单独规划或编辑某张其他图片时，使用 MCP `save_reference_image_plan`，指定 `scene_ids`、`segment_id`、
`slot_index`（0–3）和完整画面计划；无角色或无生图参考时，相应数组为空。无需重交整个 Segment 的首尾帧计划。
通过 `read_story(level="segment", extensions=["selection"])` 的 `video_inputs`，或专业工作集
`core_facts.video_inputs[]`，读取当前 recipe 的 `reference_image_plans` 与实际 `reference_inputs`。
规划的稳定 `id` 用于 `generate_media(kind="reference_image", target_id=<id>)`；只有用户明确要求生成时才调用。
候选用 `list_candidates(kind="video_reference_image", target_ids=[<id>])` 查看，取得产物 Asset ID 后用
`read_media_input` 审看真实图片；已有选图也可以直接使用 `selected_asset_id` 读取。人类在 Web 中选择后才进入视频输入。
从资产库直接绑定的图片可能没有生图计划，仍可按 `reference_inputs` 的 `asset_id`、`slot_index` 和说明读取，
不能因没有 `reference_image_plans` 就忽略它。

实际视频输入以 `video_inputs[].slots`、`require_any` 和 `reference_inputs` 为准。首尾槽位只提交已启用且已选择的图；独立图片、音频和视频参考按当前 recipe 显式绑定。
FL2VA 至少需要一个边界帧；Ref2VA 可以没有首尾帧，但必须有至少一项媒体输入。规划阶段不能自动切换 recipe。
用于生图的角色造型、地点图片和辅助图只影响生图，不自动成为视频输入；独立参考不承诺精确的起止构图。
规划阶段只能判断描述中的覆盖，不能声称已审看尚未生成的图。生成后实际画面若遗漏必要主体或空间，
必须先审核/修正该图，不能继续把计划文字当作图片内容保证。

## 可见角色与参考约束

- 每张帧只列该静态时刻真正可见的角色 ID；未出现的角色不得为了“保持一致”而加入。
- Segment 的可见角色是覆盖 Shot 的并集；段内切换后仍可见的角色都可出现在首/尾帧。
- 共享边界时允许使用两侧 Segment 的角色并集，即使该角色在另一侧随后离开。
- 空镜返回空数组。
- 不把地点图片、角色定妆图或辅助参考图称为关键帧。
- `visible_character_ids` 是用户、Planner 与 Core 共享的计划事实；用户可以在关键帧计划中显式纠正。
- 每张帧用 `start_character_references` / `end_character_references` 为可见角色选择本帧使用的造型：
  `[{character_id, look_id}]`，`look_id` 只能取自工作集 `visible_characters[].looks[].look_id`；`look_id: null`
  表示本帧不提交该角色的图。造型对应不同时期、服装或身体状态，按 `usage`（使用场合）与本帧所处剧情时刻选匹配的那一套。
- 角色只有一套造型时可以不列出该角色，Core 默认使用它；有多套造型时必须列出并选择，否则 Core 拒绝生成该帧。
  工作集同时给出造型的 `selected_asset_id` 与派生状态 `has_image`；需要核对角色外观时，用
  `read_media_input(asset_id=selected_asset_id)` 读取已选造型图。`selected_asset_id` 为 null（即 `has_image` 为 false）时
  该帧无法生成，提醒用户先为该造型设置造型图。
- Core 只提交所选造型的造型图，并在 `reference_mapping` 中标明角色与造型名；未列入可见角色的角色不得提交。
  角色造型图、前置帧与辅助参考合计最多 5 张输入图，多角色同框时尤其要精简选择。
- 用户在关键帧计划弹窗中选择的项目图片属于额外辅助参考，不替代角色卡身份参考。

## 地点语义与图片

Scene 可以绑定一个语义地点与状态；Shot 和 Keyframe 都不绑定地点图片。工作集 `location_library` 给出当前 Scene 使用的地点、
固定陈设、主光、状态和图片说明，`location_images` 列出可由人显式加入辅助参考的地点图片。Planner 应把这些事实与 Scene setting、
Shot 构图和动作一起用于写出自洽空间，但不能把地点图片当成隐藏输入，也不能假设它的机位会被复刻。

- 地点图片只是资料。只有它的已选 Asset 被人显式放入 Segment 辅助参考时，Core 才会把它提交给 Keyframe 生图。
- 没有地点图片、图片未选候选或没有合适视角时，仍应根据地点文字和镜头上下文完成画面设计，不把它报告为生成依赖缺口。
- 图片的强制 `description` 是理解实际画面的依据；`prompt_text` 只是历史生成意图，不能当成图片已实现的事实。
- 需要某张地点图片作为辅助参考时，向用户说明并由人添加到 Segment 的项目图片参考；Planner proposal 不新增或替换辅助图。
- 真正共享的边界是同一个 Keyframe，两侧自然共享同一空间结果；`continues_from_previous=true` 时只清空首帧正文和角色字段。
- 地点库后续编辑不会失效 Keyframe、视频或装配；它没有 Core 级生产绑定。

## 输出前自检

- 不读剧情文字，单看画面描述，能否知道观众先看哪里？
- 人物、道具和环境是否有明确二维位置与三维关系？
- 姿态是否是可生成的静止瞬间，而非一串动作？
- 前后帧的屏幕方向、视线、道具、光线是否无意外跳变？
- 是否错误地把普通连续剪辑标成同一张共享帧？
- 一镜到底后段是否启用首帧？
- 身份、场景和道具信息分别由哪些实际视频输入提供？是否把生图辅助图误当成视频输入？
- 尾帧是否有独立必要的时间约束？只有表情或小动作变化时能否用单首帧？独立参考已足够且没有时间约束时能否使用 none？
- 是否根据 Scene 地点与状态写出了自洽空间，同时没有把地点图片误称为自动输入或 Keyframe 绑定？

真正生成时，必须由用户明确选择或要求生成相应 Keyframe；本 Skill 本身不生成图片。


## 正文约束复核

用户明确指定的提示词语言优先于示例或旧正文。提交前逐项核对明确排除项，例如无字幕、无水印、
