# Qwen Image Prompt Writing

结构化导演脚本、Keyframe 计划和地点已经决定画面里有什么、谁在哪里、处于什么状态。本 Skill
只把这些决定翻译成 Qwen Image 2.1 擅长理解的正文写法，不重新导演画面，不新增角色、道具、剧情动作或镜头决定。
脚本信息不足以确定某个画面事实时，应返回需要上游补充的信息，不用正文自行补齐。

## 选择官方参考

先看本次实际提交的输入图（工作集 `reference_mapping` / `image_inputs`，或地点主图与视图的实际输入）：

- 没有任何输入图：读 `references/t2i-en.txt`，按其八步把画面写成观察者视角的完整描述。
- 有输入图（改图底图，或生图时的角色、地点视图、辅助参考）：读 `references/edit-en.txt`，按其属性解耦原则写编辑指令；
  有底图时属于“改这张图”，只有参考图时属于“用这些主体构建新画面”。

两个参考文件是 Qwen 官方提示词改写模板原文，原样保留。下面的 StoryRail 规则优先于模板中冲突的部分。

## StoryRail 对官方模板的覆盖

- **只输出正文**：不输出 JSON，不写 `rewritten_prompt`、`wh_ratio`、`ratio_follow`。正文直接保存为 Keyframe 或地点主图、视图的
  提示词。
- **画幅不进正文**：画布宽高由插件按项目画幅固定，Core 不在提示词里写画幅。正文不得出现画幅、分辨率、像素或
  “横版/竖版”之类的比例指令；构图仍要适配工作集给出的 `aspect_ratio`。
- **输入图指代**：Core 在提交时把输入图对应关系编译在提示词顶部，两张及以上输入图写作 `<image1>「名称」：用途`，
  只有一张时写作 `图片「名称」：用途`，顺序与实际传入一致。正文不自行编号，不写 `<imageN>`，也不写“图1”“第一张图”；
  用映射头里出现的角色名、环境名指代对应输入图，由 Core 的映射头完成名称与标签的绑定。这样角色参考增减或顺序变化时，
  已保存正文仍然正确。
- **身份来自参考图**：有角色参考图时，用名字指向该角色并写清这一刻的姿态、位置、视线、动作与服装状态；
  不用文字重新描述五官和长相，避免模型偏离参考身份。
- **语言**：用户指定正文语言时服从。未指定时：无输入图按 `t2i-en.txt` 用英文描述；有输入图按 `edit-en.txt` 跟随
  用户指令语言。画面中需要可读的文字一律保留原文字。
- **StoryRail 硬约束不变**：Keyframe 只是一张单一静态画面，不是分镜拼图；不加入剧本没有要求的文字、字幕、标志或水印。
  `t2i-en.txt` 中“为每段文字定位、定样式”的步骤只用于剧本明确存在的画内文字。
- **地点主图与视图是干净底图**：正文只写地形、建筑、空间关系、固定陈设、材质、光线与色彩；不出现人物、动物、
  剧情动作或临时道具。模板中关于人物的条目不适用。
- **Keyframe 以地点视图为底图时**：底图已经给出陈设、材质与光线，按编辑写法只写加入的人物、动作与需要变化的环境部分，
  用一句整体保留语句覆盖其余背景，不重描视图里的陈设。

## 写作流程

1. 读取工作集：目标 Keyframe 或地点主图、视图，所属 Scene / Shot / Segment 的已确定事实、可见角色与参考选择、`aspect_ratio`。
2. 判断有无输入图，选定官方参考并完整阅读。
3. 列出脚本已经固定的事实（角色、位置、动作状态、道具、光线基线、画内文字），这些必须原样进入正文。
4. 按所选模板组织正文：
   - 无输入图：先一句总述画面的媒介、风格、主体与背景；再按画面区域或主体由外到内逐处描写，大量使用位置短语，
     把画面四角、边缘与中心都写到；单独一句交代光源、方向与阴影；最后一句收束整体构图、色调与情绪。
     篇幅约四五百词，单段落。
   - 有输入图：以操作开头，说明保留什么、改变什么；被改变的属性写得明确且强烈，其余内容用一句整体保留语句覆盖，
     不逐项重描保留内容。移动、移除或揭示物体时，交代新露出区域的合理内容。单段落，保留要求用肯定句。
5. 核对：没有画幅与分辨率字样；没有自造的图片编号；没有脚本之外的新角色、新道具或新事件；画内文字逐字准确；
   用户明确的排除要求已经写进正文。

完成核对后再提交 proposal；本 Skill 不授权改写用户已保存的正文，生成时 Core 直接使用当前已保存的提示词。
