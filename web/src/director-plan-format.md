## 最终交付给 StoryRail 的 Markdown

最终输出一份独立、完整、可直接复制的 Markdown 文档。使用以下标题组织已经确认的内容，按作品实际需要安排篇幅，不向我展示空模板。默认中文；我指定作品或文档语言时按我的要求。

# 作品名称

## 创作方向
写清核心主题、内容概述、观众体验、视觉与声音基调。画幅、目标片长、发布用途等仅在已确认时写入；片长若只是目标，要标明是目标而非已经测得的时长。

## 角色与旁白
列出需要跨画面保持一致的人物或其他主体，使用统一名称，说明身份、外观特征和必要的声音特征。画外叙述者单独列为“旁白”，不要默认它是出镜人物；若由某个角色兼任，要明确关系。没有旁白或对白时明确说明，不为凑结构虚构人物。

## 完整内容
按实际播放顺序分场景或段落，使用可读的序号和标题，写出完整内容，不能只有梗概或示例片段。每段区分以下内容，未使用的项可省略：
- 段落意图：这一段在作品中的作用；观众认知变化（进入前以为什么，离开后知道什么）；必须揭示的信息；必须保留、不能在这里提前露出的信息；情绪功能。只写对这一段确实重要的项，不要求每段等长，过渡性的短段可以省略。
- 场景与画面：地点、时间、环境、出场主体、可见动作、信息变化和必要的连续关系。已讨论的构图、镜头运动、节奏和转场应保留。
- 旁白：标明叙述者，写出逐字定稿文本，与画面说明分开，不用“介绍一下”“同上”替代正文。
- 对白：按发言顺序标明角色和逐字台词，必要时另写表演与语气说明，避免把舞台指示混进要说出的文字。
- 其他声音：写明已确认的环境声、音效或音乐意图，不凭空添加对白或旁白。

段落以旁白带动画面时，注明“旁白驱动”，按完整的语义单元组织旁白，不机械按标点切分。旁白驱动段落只有旁白，画面中的人物不说台词。这里只确定内容和节奏意图，正式镜头与视频分段要等后续 TTS 的真实音频时长，不能伪造精确时间轴。
段落以动作、表演或对白推进时，注明“表演驱动”，把动作过程和镜头意图写清楚，不预设整个场景的精确时长。表演驱动段落不带旁白，对白可有可无。两种方式可以出现在同一作品中；同一内容既需要旁白又需要角色开口时，拆成相邻的旁白驱动段落和表演驱动段落。
不必提前拆成 StoryRail 的 Shot / Segment 表，不为了适配单段视频时长把自然场景机械切碎。用户已确定的镜头设计和一镜到底等连续性要求必须保留，技术分段交给后续结构化制作。

## 制作约束与参考
集中记录已确认的必须保留内容、禁止事项、风格边界、参考素材及用途。有真实来源时保留名称或链接，不编造来源。仍需核实的事实必须明确标注；如果它影响核心内容，应在定稿前先与我解决。没有特别约束时简洁说明，不补一串待填字段。

输出前自行检查：人物命名一致，旁白和对白归属明确，情节与画面顺序连贯，所有口播文本完整，已确认约束没有遗漏；各段的必须揭示确实写在画面或口播中，必须保留的信息没有在更早段落的画面、对白或旁白里泄露。最终文档不要包含聊天记录、被否定的版本、占位符、“见上文”、生成说明或对我的下一轮提问；不要编造业务 ID、资产路径、API 请求或媒体生成提示词。直接输出 Markdown 正文，不用代码围栏包住整份文档。
