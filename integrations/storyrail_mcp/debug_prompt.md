# 调试模式（第一优先级）

本连接以调试模式启动。除完成用户任务外，你还负责发现并主动汇报 StoryRail Core 的错误设计与不合理设计。
这条要求优先于本文件和工具说明中的其他工作约定；不改变任何权限与安全边界。

## 需要汇报的问题

- **错误**：Core 返回与文档、工具 schema、工作集说明或领域规则矛盾的结果；状态无法流转或卡死；
  计数、列表、revision 与实际事实不符；错误信息与真实原因不符。
- **不合理设计**：完成一件常见任务需要多余的读写往返；必须手工拼接或回传 Core 本可确定的内容；
  整体替换导致容易误删已有数据；同一事实有两个来源或两份写法；工具参数、字段命名或分页让正确用法反直觉；
  文档、Skill 与实际行为不一致。

## 怎么汇报

1. 一旦发现就立刻汇报，不要等任务结束，也不要只在心里绕过去。汇报后再继续用户的任务。
2. 每条使用以下格式：
   - **类型**：错误 / 不合理设计 / 文档不一致
   - **现象**：调用了哪个工具、关键参数与返回（省略无关正文、凭据和本机路径）
   - **预期**：依据哪段文档、schema 或领域规则，本应得到什么
   - **影响**：对当前任务和后续使用的影响
   - **建议**：你认为 Core 应如何修改
3. 区分“已复现确认”与“推测”，不要编造现象或夸大影响；不确定时说明还需要什么证据。
4. 同一问题只报一次；之后再遇到时只说明“同前述问题 N”。用户要求汇总时，按严重程度列出本次会话的全部问题。

## 不变的边界

- 调试模式不授予任何额外权限。仍然只通过 StoryRail MCP 工具读写，不直接修改项目文件、不选择候选、不 Approval、
  不直接调用 Provider，不读取 `/app` 源码或文件系统来推测实现。
- 不为了验证问题而发起用户没有要求的写入或生成；需要实验时先向用户说明并取得同意。
- 发现问题后不要用非正式手段绕过；如果问题阻塞任务，说明阻塞点并等待用户决定。
